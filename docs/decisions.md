# Decision log

Format: date · decision · why · alternatives considered.

## D1 — 2026-11-20 · Stack: C++20 sim + C11 firmware, SDL2 + Dear ImGui + ImPlot, MSYS2 UCRT64 at `D:\msys64`
- **Why:** native C/C++ links firmware directly; ImPlot gives fast live plots; GCC matches the arm-none-eabi-gcc used for STM32; MSYS2 pacman provides GCC/CMake/Ninja/SDL2 in one place; D: chosen to save C: space.
- **Installed (2026-11-20):** GCC 16.2.0, CMake 4.5.0, Ninja 1.13.2, GDB 18.1, SDL2 2.32.10, clang-format 23.1.5, Python 3.14.10 (all MSYS2 UCRT64).
- **PATH policy:** persistent system/user PATH is not modified; `cmake/toolchain-msys2-ucrt64.cmake` pins compilers/Ninja under `MSYS2_ROOT` (default `D:/msys64`), so legacy `C:\MinGW` GCC 6.3 is never used.
- **Alternatives:** Qt 6 (heavy, LGPL, slower iteration); raylib (weak UI/plots); Web UI + C++ backend (two codebases); MSVC Build Tools (different compiler family from STM32 GCC).

## D2 — 2026-11-20 · Firmware runs as a DLL in lockstep with sim time
- **Why:** unload/reload gives clean firmware globals on reset and hot-reload after rebuild; lockstep (ISR on sim thread, main loop resumes only at blocking HAL calls) makes runs bit-deterministic.
- **Trade-off:** real ISR-preemption races are not reproduced (documented limitation).
- **Alternatives:** static link into the sim exe (no clean reset of globals); free-running threads (non-deterministic); MCU emulation via QEMU/Renode (out of scope, much slower iteration).

## D3 — 2026-11-20 · Dependencies pinned by archive hash via FetchContent

- **Why:** reproducible builds without vendoring; CI and local fetch identical sources.

## D5 — 2026-11-20 · GUI deps, renderer, visual verification, static runtime
- **Deps (Slice 2):** Dear ImGui 1.93.0-docking, ImPlot 1.1, stb @ `6b5799b` (stb_image_write), SHA-256 pinned; SDL2 2.32.10 from MSYS2. Backend: SDL2 + SDL_Renderer (D3D11), per the ImGui `example_sdl2_sdlrenderer2` of the same version.
- **Visual test = real renderer.** `mmsim --verify-render` pixel-checks every wall slot (present/absent) and post against the maze on the accelerated renderer. SDL's `--software` rasterizer leaves a 1-px seam on the diagonal of thin wall quads and drops some ~3-px post squares, so it is diagnostic only. Probes sample a strip across the wall thickness (robust to seams, still fails on any missing/extra wall).
- **Static C/C++ runtime:** all exes/DLLs link `-static-libgcc -static-libstdc++` + static winpthread. Reason: `C:\MinGW\bin` (GCC 6.3) is on PATH and would otherwise supply an ABI-incompatible `libstdc++-6.dll`. Only `SDL2.dll` is copied next to `mmsim.exe`.
- **Geometry lives in `sim/core/maze_geometry`** (metres; origin = centre of SW post; 180 mm pitch, 12 mm walls) so physics/raycast reuse exactly what is drawn.
- **Amended in Slice 3:** shared libraries (= firmware DLLs, pure C) link only `-static-libgcc`; whole-archive winpthread stays exe-only because a DLL that is `FreeLibrary`'d on every reset should not carry pthread TLS callbacks.
- **Maze text parser follows mms semantics:** any non-space char at a wall position is a wall (`+` or `o` posts); `.maz` = N*N bytes column-major, low nibble only.

## D6 — 2026-11-20 · Firmware main runs on a Win32 fiber; physics model and collision choices (Slice 3)
- **Fiber, not thread.** `fw_main` runs on a fiber (`sim/platform/fiber`); `FirmwareHost` switches to it only at t=0 and when a blocking HAL call's deadline is reached; the SysTick ISR runs on the caller's stack after each 1 ms physics tick. Same lockstep semantics as D2 with a ~1 µs switch instead of 5–20 µs thread hand-offs (needed for the ≥ 50× headless target). Reset = delete the suspended fiber + `FreeLibrary` + load a fresh private copy of the DLL (copy-on-load also allows rebuilding while the sim runs and gives parallel sessions separate globals).
- **Faults:** blocking call inside the ISR → `Faulted` (motors zeroed); `fw_main` returning → `Halted`; a busy-wait polling `hal_millis/micros` yields a tick every 256 reads. A loop with no HAL calls at all cannot be pre-empted: `run_guarded` runs the session on a worker thread and, after a wall-clock timeout (GUI: 2 s), reports `Hung` and abandons that thread + session.
- **Drive model:** DC motor (R, Kt, Ke, gear, rotor/wheel inertia, viscous + Coulomb friction with stiction, efficiency) coupled through the rigid-body mass matrix in wheel-speed coordinates; integrated implicitly in the decoupled sum/difference modes at 0.25 ms, so symmetric inputs give exactly straight lines and exact pivots; pose by exact arc integration. Verified against closed-form solutions (τ within 0.3 %, arc radius 1e-9, zero heading drift over 10 m). Wheel slip: see D7. Terminal voltage = duty × battery, clamped to `motor.max_voltage` (6 V for N20 on 2S) with a counted warning.
- **Collision:** body = oriented rectangle (exactly what is drawn) vs wall/post AABBs (SAT + minimum translation), uniform-grid broadphase, swept sampling ≤ half a wall thickness per sample + 12-step bisection to the last free pose; response zeroes or reverses (×restitution) wheel speeds; one `CrashEvent` per contact begin. No tunnelling at 20 m/s; penetration ≈ 2e-5 mm at 0.8 m/s.
- **arm-check** compiles each firmware to an object with `-O2 -Werror -Wdouble-promotion` for Cortex-M4F (stricter than the planned `-fsyntax-only`, which skips codegen warnings).
- **Alternatives:** OS threads + condition variables (planned in 3.3; too slow per tick); setjmp/longjmp stacks (non-portable stack switching); explicit RK4 (needs smaller steps for the stiff motor pole, no exact symmetry); polygon body (rectangle suffices until a real chassis outline arrives in Phase 2).

## D7 — 2026-11-20 · HAL v2 sensors, deterministic noise, linear tyre slip (Slice 4)
- **HAL v2** (`MMHAL_VERSION 2`, `MMSIM_HOST_ABI 2`): adds `hal_get_encoders`, `hal_get_gyro` / `hal_get_accel` (3-axis structs, body frame x fwd / y left / z up) and `hal_get_distance(ch)` -> mm or `HAL_DISTANCE_NONE` (0xFFFF). v1 calls are unchanged. Channel order for the presets: 0 = left/diag_left, 1 = front_left, 2 = front_right, 3 = right/diag_right. `hal_get_gyro_z_dps` now returns the *measured* rate (noise, bias, quantisation), never ground truth.
- **Sensors** (`sim/core/sensors`): each channel samples on 1 ms tick boundaries at its own `rate_hz`, draws noise **at sample time** from its own stream, and delivers after `latency_ms` - so readings never depend on how often firmware reads them. Beam = `rays` rays across `fov_deg`, weighted `edge_weight^((off/half)^2)` (Gaussian-like profile). ToF = nearest hit in the cone; IR = ambient + weighted mean of `gain * cos(incidence)^p / (d + d0)^2` ADC counts. `hal_get_distance` for IR uses the inverse of that model ("board calibration"), so it is exact for a perpendicular wall and biased at oblique angles, like a real calibrated IR. IR emitters default ON (the board pulses them); `hal_emitter_set(ch, false)` leaves ambient only and distance NONE. Presets `front_side` / `front_diagonal` + per-sensor overrides in JSON.
- **Raycast:** slab-method ray vs wall/post AABBs through the same uniform grid as collision (exact; ray starting inside a box gives t = 0).
- **Noise & PRNG:** `xoshiro256**` per source, seeded `splitmix64(world_seed ^ FNV-1a(stream name))`; Box-Muller without a cached spare. Adding a sensor never changes the other streams; `--seed N` (GUI/CLI) sets the world seed. Distance noise sigma = `noise_sigma + noise_rel * value`, then quantisation. IMU: white noise, constant bias + random-walk bias, quantisation (LSB), range clamp; accelerometer = world velocity change over the tick in the body frame + gravity on z.
- **Encoders:** `floor(angle * CPR / 2pi + 1e-9)` (a decoder counts edges passed; floor, not round), per-side wiring inversion, int32 wrap. CPR = `counts_per_motor_rev * gear_ratio`.
- **Linear tyre slip (Peter Harrison's slip-gradient idea), opt-in** (`slip.enabled`, on in `generic_classic.json`, off in the struct default so Slice 3 results stay exact):
  - Longitudinal: per wheel `F = C (r w - u)` with `u` the contact-patch ground speed, capped at `mu m g / 2`. Body `v`, `w` become states. Backward Euler in the decoupled sum/difference modes (2x2 each, so symmetric inputs stay exactly straight / exactly in place); if a wheel saturates its force is fixed at the limit and the 4x4 system is solved by Gaussian elimination. Result: acceleration capped at `mu g`, wheels spin up and odometry over-reads.
  - Lateral: slip angle `beta = k * a_lat`, `k = slip_gradient_deg_per_g * pi/180 / g`, `a_lat = v w` clamped to `mu g`; the velocity direction `phi = theta - beta` may turn at most `mu g dt / |v|` per step (skid). Pose moves along mid-`phi`.
  - Wall contact with slip: body `v`/`w` are zeroed/reversed (x restitution) and `beta` reset; the wheels keep spinning, so encoders keep counting while pinned (as on a real mouse).
- **Alternatives:** Pacejka magic formula (too many unknown parameters for a generic mouse; linear + cap captures the behaviour that matters for control tuning); per-read noise (makes results depend on firmware polling rate); one global RNG (adding a channel would shift every other stream).

## D8 — 2026-11-20 · Demo firmware design, motor safety in firmware, GUI pacing (Slice 5)
- **`firmware/demo_floodfill/`** (pure C11, mmhal only, ARM-clean): `control.c` 1 kHz ISR (encoder odometry, gyro heading with a 300 ms bias calibration at boot, trapezoidal profiles, PD position loops on per-tick accumulated errors plus motor-model feed-forward per wheel: kV = 4.38 V/(m/s), kA = 0.24 V/(m/s^2), static 0.1 V), `sensors.c` (diagonal wall following, wall thresholds), `maze.c` (BFS flood fill; search = unknown walls open, speed run = known-open walls only), `mouse.c` (moves, search, speed run), `motors.c`, `profile.c`, `main.c` (state machine).
- **Search pattern:** walls of a cell are read at its entry boundary (diagonals see that cell's side walls ~20 mm past its centre; the front sensors see its front wall at ~125 mm). Straight on = keep moving; a turn = stop at the centre, square up on a front wall if there is one (front sensors to 34 mm and equal), turn in place with the gyro, go. Steering stops when a front wall is within 80 mm (the diagonals would see it).
- **Calibration constants** (`config.h`) were measured in the simulator, the way a real robot is calibrated: diagonal 109 mm when centred, 1.68 mm per mm of offset, ~4.2 mm per degree; thresholds 140 mm (side) and 170 mm (front at a boundary).
- **Motor safety lives in the firmware** (`motors.c`), as on the robot: terminal voltage capped at 6.0 V (duty = V / V_battery, never 100 % PWM); every change of direction passes through >= 20 ms at 0 V (time already spent at 0 V counts). The simulator's own `max_voltage` clamp stays as a second line of defence.
- **Results (seed 1):** UK 1987 search 42 s, return 34 s, speed run 21 s, total 97 s simulated, 0 crashes, every mapped wall correct; same for seeds 2-3, three generated mazes and UK 1988/2000/2017. Debug and Release builds give bit-identical runs.
- **Pacing (`sim/host/pacer`):** fractional accumulator, sim ms = speed x wall time with no per-frame rounding drift; frames longer than 100 ms are not caught up (reported as behind); Max runs as many ticks as fit in 12 ms per frame. Measured with `mmsim --live-for`: 60 s at 1x -> 60.006 s simulated in 60.006 s wall; 2x/5x/10x within 0.01 %; Max ~64x (Release, visible window). Headless (Release) runs UK 1987's whole mission at ~135x real time.
- **Deferred:** smooth (arc) search turns and diagonal speed runs - in-place turns are robust and well inside the 5 min budget; cell-colour annotations are sent but drawn only in Slice 6.
- **Alternatives:** stop-at-every-cell search (simpler, ~2x slower); deciding at the cell centre (no time to brake from search speed); absolute heading tracking (front-wall squaring + steering keep relative heading error bounded without it).
